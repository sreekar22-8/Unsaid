## 1. MAIN PRIORITY — AI CHAT RESPONSES

The biggest current problem is that emotion detection works, but AI responses are sometimes generic, repeated, or unrelated to the user's actual message.

Examples from current testing:

* "hello how are you" → uncertain 0.3 → generic emotional-weight response
* "i am sad" → sadness 0.8 → generic sadness response
* "i had a good day today" → hopeful 0.8 → generic emotional response
* "hello" / "bye" → sometimes produce an unrelated regret-style response
* "help me" → Help mode gives an appropriate help-style response
* "i am good now" → hopeful 0.8 but sometimes receives the same Help-style response

Trace the COMPLETE flow:

frontend input
→ conversation creation/loading
→ chat API
→ emotion classification
→ mode selection
→ conversation history
→ approved memory retrieval
→ generateCompanionReply
→ Gemini/API request
→ response parsing
→ fallback handling
→ database persistence
→ frontend rendering.

Determine the exact root cause.

Check specifically:

* Is Gemini actually being called?
* Is the latest user message included in the Gemini request?
* Is the selected mode included?
* Is the detected emotion included correctly?
* Is conversation history correct and in the correct role order?
* Is an old conversation/message being reused accidentally?
* Is the Gemini response being parsed correctly?
* Is an exception silently causing replyFor() to run?
* Are catch blocks hiding API errors?
* Is replyFor() being called when Gemini succeeds?
* Is the frontend displaying a previous response?
* Is state being updated incorrectly after sending a message?
* Is there any stale/cached response?
* Is the same fallback/template being selected because of incorrect mode/emotion data?

Fix the root cause, not just the visible symptom.

The final AI response must be based primarily on the user's CURRENT message while naturally considering conversation history and approved memories.

Do not simply create many hard-coded replies for individual test messages.

## 2. ALL FOUR MODES

Verify and fix all existing modes:

### Listen

Should primarily listen, acknowledge, and reflect what the user actually said.

### Understand

Should help identify/explore the feeling underneath the user's message.

### Reframe

Should offer a compassionate alternative perspective based on what the user actually said.

### Help

### Private
